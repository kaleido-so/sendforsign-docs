All tools return JSON (as text and as `structuredContent`). Errors come back as tool errors with a readable
message, for example `Blocked by policy: ...` or `Sendforsign API error (404): ...`. Each tool calls the public
[REST API](/api-reference/introapi), so the same permissions apply.

| Tool | What it does | Writes | Emails people | Needs mode |
|---|---|---|---|---|
| [`get_connection_info`](#get_connection_info) | Mode, tenant, allowed domains, audit status of this connection | no | no | any |
| [`list_templates`](#list_templates) | Templates of the account or tenant | no | no | any |
| [`get_template`](#get_template) | A template and its fields, with who fills each | no | no | any |
| [`list_contracts`](#list_contracts) | Contracts with status, filterable | no | no | any |
| [`get_contract`](#get_contract) | A contract: status, template, recipients, fields, optional body | no | no | any |
| [`create_contract`](#create_contract) | Draft from a template or from Markdown/HTML, fill fields, attach recipients | yes | **no** | `draft` |
| [`update_contract`](#update_contract) | Rename a draft or replace its body | yes | no | `draft` |
| [`create_pdf_contract`](#create_pdf_contract) | Draft from a PDF (https URL or base64), return page sizes | yes | **no** | `draft` |
| [`place_pdf_fields`](#place_pdf_fields) | Put signature, date, name, email and text fields on PDF pages | yes | no | `draft` |
| [`list_placeholders`](#list_placeholders) | Fields of a contract or template | no | no | any |
| [`fill_placeholders`](#fill_placeholders) | Set field values; change who fills a field | yes | no | `draft` |
| [`add_recipients`](#add_recipients) | Add signers/approvers/viewers, return signing links | yes | **no** | `draft` |
| [`list_recipients`](#list_recipients) | Recipients with role, order and signing link | no | no | any |
| [`send_for_signature`](#send_for_signature) | Email signing invitations; `confirm: true` required | yes | **yes** | `send` |
| [`get_contract_timeline`](#get_contract_timeline) | Events (created, sent, seen, signed…) plus agent actions | no | no | any |
| [`download_contract_pdf`](#download_contract_pdf) | The contract as a PDF, with signatures once signed | no | no | any |
| [`archive_contract`](#archive_contract) | Archive a contract; `confirm: true` required | yes | no | `send` |
| [`list_users`](#list_users) | Tenants (users) of the client, for embedded products | no | no | any |
| [`create_user`](#create_user) | Create a tenant and return its `userKey` | yes | no | `draft` |
| [`create_template`](#create_template) | Template from Markdown/HTML with `{{field}}` markers | yes | no | `draft` |
| [`update_template`](#update_template) | Rename a template or replace its body | yes | no | `draft` |
| [`create_pdf_template`](#create_pdf_template) | Template from a PDF (https URL or base64) | yes | no | `draft` |
| [`create_template_from_contract`](#create_template_from_contract) | Save a contract as a template | yes | no | `draft` |
| [`duplicate_template`](#duplicate_template) | Copy a template with its fields | yes | no | `draft` |
| [`delete_template`](#delete_template) | Delete a template; `confirm: true` required | yes | no | `send` |
| [`duplicate_contract`](#duplicate_contract) | Copy a contract as a new draft | yes | no | `draft` |
| [`remove_field`](#remove_field) | Delete a field from a contract or template | yes | no | `draft` |
| [`update_recipient`](#update_recipient) | Change a recipient's name, email, role, order or message | yes | no | `draft` |
| [`remove_recipient`](#remove_recipient) | Remove a recipient from a contract | yes | no | `draft` |
| [`get_usage`](#get_usage) | Contracts sent this period vs the plan limit | no | no | any |
| [`list_webhooks`](#list_webhooks) | Webhook URLs and their events (no secrets) | no | no | any |
| [`create_webhook`](#create_webhook) | Register a webhook URL; `confirm: true` required | yes | no | `send` |
| [`delete_webhook`](#delete_webhook) | Remove a webhook; `confirm: true` required | yes | no | `send` |

"Needs mode" is the lowest [agent mode](/ai-agents/accountability#agent-modes) that allows the tool: `read_only` <
`draft` < `send`. Tools are annotated for MCP clients: read tools carry `readOnlyHint`, `archive_contract`, `delete_template` and the webhook
tools carry `destructiveHint`, and `send_for_signature` carries `openWorldHint` (it reaches people outside the conversation), so
clients that ask before risky calls can do so.

Most tools accept an optional `userKey` argument that selects the tenant for that call; without it, the
`X-Sendforsign-User-Key` header or the account's default user is used. On an OAuth connection where a user was picked
on the consent screen, that user is a limit: a different `userKey` is refused with
`Blocked by policy: this connection is limited to userKey …`, and `list_users` / `create_user` are blocked.

## Field roles (`filledBy`)

Tools describe template and contract fields with a `filledBy` value that maps to the REST
[`fillingType`](/usecase/placeholder-filler):

| `filledBy` | `fillingType` | Who fills the field |
|---|---|---|
| `none` | `1` | Nobody; a fixed value |
| `owner` | `2` | The contract owner — the agent or your user, before sending |
| `any_recipient` | `3` | Whichever recipient opens the contract |
| `specific_recipient` | `4` | One recipient, given by `recipientKey` |

The agent should fill only `owner` fields and leave recipient fields to the recipients.

---

### get_connection_info

Shows how this connection is configured. Call it first if unsure what you are allowed to do.

**Arguments:** none.

**Returns:** `mode`, `clientKey`, `userKey`, `agent`, `onBehalfOf`, `allowedRecipientDomains` (`"any"` or a list),
`auditLog` (`"on"`/`"off"`), `auth` (`"oauth"` or `"header"`), `userKeyIsLimit` (`true` when an OAuth grant is
restricted to one user), `sendingRequiresConfirm: true`.

### list_templates

Lists templates available to the account or tenant. Use a template whenever the user asks for a standard document
(NDA, service agreement, offer) before drafting from scratch.

**Arguments:** `userKey?`

**Returns:** `templates[]` with `templateKey`, `name`, `changeTime`.

### get_template

A template and its fields, including who fills each.

**Arguments:** `templateKey`, `includeContent?` (default `false`; `true` adds the HTML body), `userKey?`

**Returns:** `templateKey`, `name`, `placeholders[]` (`placeholderKey`, `name`, `value`, `filledBy`, `recipientKey`),
`content?`.

### list_contracts

Lists contracts with their status.

**Arguments:** `status?` (e.g. `Created`, `Sent`, `Seen`, `Signed`, `Fully signed`, `Archived`; case-insensitive),
`nameContains?`, `limit?` (1–500, default 50), `userKey?`

**Returns:** `total`, `contracts[]` with `contractKey`, `name`, `status`, `createTime`, `changeTime`.

### get_contract

**Arguments:** `contractKey`, `includeContent?` (default `false`), `userKey?`

**Returns:** `contractKey`, `name`, `status`, `templateKey` (the template it was created from, or `null`),
`createTime`, `changeTime`, `recipients[]` (with `signingUrl`), `placeholders[]`, `content?`.

### create_contract

Creates a **draft** contract. It never emails anyone, even when you pass recipients.

**Arguments:**

| Name | Type | Notes |
|---|---|---|
| `name` | string | Contract title. Required. |
| `templateKey` | string | Preferred. Build from this template. |
| `content` | string | Body when not using a template. |
| `contentFormat` | `markdown` \| `html` | Default `markdown`. |
| `fields` | array of `{ placeholderKey?, name?, value }` | Values for template fields. `placeholderKey` may be the template's key (from `get_template`); it is mapped to the contract's field of the same name, since a new contract gets new field keys. `name` matches case-insensitively. Only owner fields. |
| `recipients` | array of recipients | `{ fullname, email, action?, position?, customMessage? }`; `action` is `sign` (default), `approve`, `view` or `lock`. Checked against the domain allowlist. |
| `userKey` | string | Tenant. |

Pass `templateKey` or `content`.

**Fields in your own text.** In `content`, mark fields with double braces and they become real fields:

| Marker | Field |
|---|---|
| `{{Name}}` | Your side fills it later (`fill_placeholders`) |
| `{{Name=Value}}` | Your side, filled now |
| `{{Name@any}}` | Any recipient fills it |
| `{{Name@jane@acme.com}}` | That recipient fills it; pass them in `recipients` |

The same name used twice is one field (its value appears in both places). Values are inserted as text, never as
HTML. Triple braces (`{{{Name}}}`) are left alone. Example:

```markdown
Fee: {{Fee=2 400 EUR}}, payable by {{Client company@any}}.
Signed for the client by {{Signer title@jane@acme.com}}.
```

**Returns:** `contractKey`, `status: "draft"`, `recipients[]` with `signingUrl`, `filled[]` (per field: `field`,
`ok`, `error?`) when `fields` were given, `fieldsFromText[]` (name, `placeholderKey`, `filledBy`, recipient, value)
when `content` had markers, `unfilledFields[]` (owner and fixed fields still empty),
`fieldsForRecipients[]`, and `next` — a hint for the next step.

### update_contract

Renames a draft and/or replaces its body. Only for contracts that have not been sent.

**Arguments:** `contractKey`, `name?`, `content?`, `contentFormat?` (default `markdown`), `userKey?`

`content` may contain the same field markers as `create_contract`. A marker with the name of an existing field reuses
that field (same `placeholderKey`, so values and roles carry over); new names create new fields.

**Returns:** `contractKey`, `updated[]` (the fields changed), `fieldsFromText[]` when `content` had markers.

### create_pdf_contract

Creates a **draft** contract from a PDF. It never emails anyone.

**Arguments:**

| Name | Type | Notes |
|---|---|---|
| `name` | string | Contract title. Required. |
| `pdfUrl` | string | Public `https://` URL of the PDF. Private and internal addresses are refused. |
| `pdfBase64` | string | The PDF as base64 (a `data:application/pdf;base64,` prefix is fine). |
| `recipients` | array of recipients | As in `create_contract`. Needed before placing their fields. |
| `userKey` | string | Tenant. |

Pass exactly one of `pdfUrl` or `pdfBase64`. Up to 20 MB.

**Returns:** `contractKey`, `status: "draft"`, `pages[]` (`page`, `widthPt`, `heightPt`), `recipients[]` with
`signingUrl`, and `next`.

### place_pdf_fields

Puts fields on the pages of a draft PDF contract, or of a PDF template. Calling it again adds fields; it does not
remove earlier ones. On a template (`templateKey`) only `text` fields with `filledBy` `owner` or `any_recipient` are
allowed: a template has no recipients yet, so signature, date, name and email boxes go on each contract made from it.

**Arguments:** `contractKey` or `templateKey`, `fields[]`, `userKey?`. Each field:

| Name | Type | Notes |
|---|---|---|
| `kind` | `signature` \| `date_signed` \| `full_name` \| `email` \| `text` | The first four are filled from the recipient when they sign. |
| `page` | number \| `"last"` | 1-based page. |
| `x`, `y` | number | Top-left corner of the box, in percent of the page width and height. |
| `width`, `height` | number | Size of the box, in percent of the page width and height. |
| `recipient` | email | Required for `signature`, `date_signed`, `full_name`, `email`; for `text`, the recipient who fills it. |
| `name` | string | `text` fields: the field name. The same name on several boxes is one field. |
| `value` | string | `text` fields your side fills now. |
| `filledBy` | `owner` \| `any_recipient` \| `specific_recipient` | `text` fields. Default `owner`, or `specific_recipient` when `recipient` is given. |

Example: a signature and the signing date at the bottom right of the last page.

```json
{ "contractKey": "…", "fields": [
  { "kind": "signature",   "page": "last", "x": 60, "y": 80, "width": 30, "height": 8, "recipient": "jane@acme.com" },
  { "kind": "date_signed", "page": "last", "x": 60, "y": 89, "width": 30, "height": 3, "recipient": "jane@acme.com" }
] }
```

**Returns:** `contractKey`, `placed[]` (kind, page, recipient or field name), `pages`, `next`.

### list_placeholders

**Arguments:** `contractKey?` or `templateKey?` (one is required)

**Returns:** `placeholders[]` with `placeholderKey`, `name`, `value`, `filledBy`, `recipientKey`.

### fill_placeholders

Sets field values in a contract or a template, by `placeholderKey` or by name (case-insensitive), and can change who
fills a field (`specific_recipient` is for contracts only).

**Arguments:** `contractKey` or `templateKey`, `fields[]` of `{ placeholderKey?, name?, value?, filledBy?, recipientKey? }`.
`recipientKey` is required when `filledBy` is `specific_recipient`. Changing `filledBy` to anything else clears the
assigned recipient.

**Returns:** `contractKey`, `results[]` with `field`, `placeholderKey`, `ok`, `error?` per field. One failed field
does not stop the others.

### add_recipients

Adds signers, approvers or viewers **without emailing them**. Signing order continues after existing recipients
unless you pass `position`.

**Arguments:** `contractKey`, `recipients[]` (as in `create_contract`, at least one), `userKey?`

**Returns:** `contractKey`, `recipients[]` (all recipients of the contract) with `recipientKey` and `signingUrl`.

The `signingUrl` (`https://app.sendforsign.com/sharing/{recipientKey}`) can be shown in your own product instead of
sending email. See [embedded signing](/ai-agents/recipes#embedded-signing-without-email).

### list_recipients

**Arguments:** `contractKey`

**Returns:** `contractKey`, `recipients[]` with `recipientKey`, `fullname`, `email`, `action`, `position`,
`customMessage`, `signingUrl`.

### send_for_signature

**Emails** signing invitations. This contacts real people.

Before calling, the agent must show the user the contract name, the recipients and their roles, get explicit
approval, and then pass `confirm: true`. Without it the tool returns `Not executed: ... needs confirm: true` and sends
nothing. Allowed only in `send` mode; recipients are checked against the domain allowlist.

**Arguments:** `contractKey`, `confirm` (boolean, must be `true`), `recipientKeys?` (send only to these; default: all
recipients), `customMessage?` (overrides the invitation message), `userKey?`

**Returns:** `contractKey`, `sentTo[]` with `email`, `action`, `signingUrl`.

### get_contract_timeline

Event history of a contract, plus the agent actions recorded for it when the audit log is on.

**Arguments:** `contractKey`

**Returns:** `contractKey`, `events[]` (`time`, `status`, `name`, `email`), `agentActions[]?` (`create_time`, `agent`,
`on_behalf_of`, `mode`, `tool`, `outcome`, `message`, `hash`).

### download_contract_pdf

**Arguments:** `contractKey`

**Returns:** `contractKey`, `mimeType: "application/pdf"`, `bytes`, `base64`.

### archive_contract

Archives a contract: it leaves active lists and can no longer be signed. Needs `confirm: true` after explicit user
approval, and `send` mode.

**Arguments:** `contractKey`, `confirm`, `userKey?`

**Returns:** `contractKey`, `archived: true`.

### list_users

For products that embed Sendforsign: lists tenants (users) of the client. Each has its own templates and contracts,
addressed by `userKey`.

**Arguments:** none.

**Returns:** `users[]` with `userKey`, `fullname`, `email`, `customKey`.

### create_user

Creates a tenant and returns its `userKey`. `customKey` is your own ID for it, so you can map back.

**Arguments:** `fullname`, `email`, `customKey?`

**Returns:** `userKey`, `fullname`, `email`, `customKey`.

### create_template

Creates a reusable template from text. Fields are marked in the text: `{{Name}}` (your side fills it on each
contract), `{{Name=Value}}` (with a default) and `{{Name@any}}` (the recipient fills it when signing).
`{{Name@email}}` is refused, because a template has no recipients yet.

**Arguments:** `name`, `content`, `contentFormat?` (`markdown` default, or `html`), `userKey?`

**Returns:** `templateKey`, `name`, `fields[]` with `name`, `placeholderKey`, `filledBy`, `value`.

### update_template

Renames a template and/or replaces its body, with the same markers. A field keeps its key when the same name is used
again. Contracts already made from the template do not change.

**Arguments:** `templateKey`, `name?`, `content?`, `contentFormat?`, `userKey?`

### create_pdf_template

Creates a PDF template from a PDF by https URL (`pdfUrl`) or base64 (`pdfBase64`), up to 20 MB, and returns the page
sizes. Add text fields with [`place_pdf_fields`](#place_pdf_fields) and `templateKey`. Contracts made from it with
`create_contract` get the PDF and those fields.

**Arguments:** `name`, `pdfUrl?` or `pdfBase64?`, `userKey?`

**Returns:** `templateKey`, `name`, `pages[]`.

### create_template_from_contract

Saves an existing contract (its text and fields) as a new template.

**Arguments:** `contractKey`, `name`, `userKey?` · **Returns:** `templateKey`.

### duplicate_template

**Arguments:** `templateKey`, `userKey?` · **Returns:** the copy's `templateKey`.

### delete_template

Deletes a template; contracts made from it are not affected. Needs `confirm: true` and `send` mode.

**Arguments:** `templateKey`, `confirm`, `userKey?`

### duplicate_contract

Copies a contract as a new draft, without recipients.

**Arguments:** `contractKey`, `userKey?` · **Returns:** the new `contractKey`.

### remove_field

Deletes a field from a contract or a template, with its tags in the text.

**Arguments:** `contractKey` or `templateKey`, `placeholderKey`

### update_recipient

Changes a recipient's `fullname`, `email`, `action`, `position` or `customMessage`. Emails nobody. A new email must be
in the connection's allowed domains.

**Arguments:** `contractKey`, `recipientKey`, any of the fields above, `userKey?` · **Returns:** `recipients[]`.

### remove_recipient

Removes a recipient; their signing link stops working. Emails nobody.

**Arguments:** `contractKey`, `recipientKey`, `userKey?` · **Returns:** `recipients[]`.

### get_usage

Contracts sent this billing period against the plan limit, and the count for this connection's client. Same numbers
as [`GET /api/usage`](/api-reference/usage).

### list_webhooks

Webhook URLs of the client and the events each receives. Secrets are not returned.

### create_webhook

Registers an https URL that receives contract events, which include recipients' names and emails. Use only a URL the
user owns and confirmed: needs `confirm: true` and `send` mode. Without event flags it subscribes to all events.

**Arguments:** `url`, `created?`, `sent?`, `seen?`, `approved?`, `signed?`, `fullySigned?`, `confirm`

**Returns:** `webhookKey`, `url`, `events`, `secret` (shown once; use it to verify the signature).

### delete_webhook

**Arguments:** `webhookKey`, `confirm` (needs `send` mode).

The Sendforsign MCP server is a remote server over **Streamable HTTP**:

```bash
https://api.sendforsign.com/mcp
```

There are two ways to connect:

- **Sign in with Sendforsign (OAuth)** — for AI apps people use: Claude, ChatGPT, Claude Code, Cursor, VS Code. Paste
  the URL, sign in, and choose on the consent screen which account the app may use and what it may do. No API key is
  copied anywhere.
- **API key in headers** — for [server-side agents](#server-side-agents-api-key) you run yourself, where your code
  sets the account and the guardrails per connection.

## Connect an AI app

Every client below follows the same three steps:

1. Add the server URL `https://api.sendforsign.com/mcp`.
2. Sign in to Sendforsign in the browser window that opens (or create an account).
3. On the consent screen, choose:
   - **Account** — the client (`clientKey`) the app works in, and optionally a **user** (tenant) inside it. If you pick
     a user, the connector can only act as that user and cannot list or create users. Without one, it works at the
     account level and can address any user of the account.
   - **What the agent may do** — *read only*, *create drafts* (the default) or *send for signature*. Even with
     *send*, every email still needs your explicit approval in the chat (`confirm: true`).
   - **Allowed recipient domains** (optional) — the app cannot send contracts to anyone outside them.

You can change these later only by disconnecting and connecting again. See
[modes and accountability](/ai-agents/accountability) for what each choice means.

  <Tab title="Any OAuth client">
    The server implements the MCP authorization spec: **OAuth 2.1** with **dynamic client registration** (RFC 7591)
    and **PKCE** (S256). A compliant MCP client needs only the URL.

    | Step | Endpoint |
    |---|---|
    | Unauthenticated `POST /mcp` | `401` with `WWW-Authenticate: Bearer resource_metadata="…"` |
    | Protected resource metadata | `https://api.sendforsign.com/.well-known/oauth-protected-resource/mcp` |
    | Authorization server metadata | `https://api.sendforsign.com/.well-known/oauth-authorization-server` (issuer `https://api.sendforsign.com/`) |
    | Registration, authorization, token, revocation | Listed in the metadata (`/register`, `/authorize`, `/token`, `/revoke`) |

    Details:
    - One scope: `contracts`. What the agent may do is set by the mode chosen on the consent screen, not by scopes.
    - Send the `resource` parameter (`https://api.sendforsign.com/mcp`) in the authorization and token requests.
    - Access tokens last 1 hour. Refresh tokens last 90 days and **rotate on every use**; reusing an old refresh token
      or an authorization code revokes the whole connection.
    - The OpenAI Agents SDK and other SDKs connect the same way when given an OAuth provider; for an agent that runs
      on your servers without a person signing in, use an [API key](#server-side-agents-api-key) instead.
  </Tab>
</Tabs>

## Try it

Ask the agent:

> What can you do with Sendforsign on this connection?

It calls [`get_connection_info`](/ai-agents/tools#get_connection_info) and tells you its mode, account and allowed
domains. Then:

> List my templates. Draft an NDA from the NDA template for Acme Ltd, signer Anna Smith, anna@example.com.
> Show me what you filled in and the signing link. Don't send it yet.

The agent uses `list_templates` → `get_template` → `create_contract`, returns a draft with a `signingUrl` and lists
the fields left for the counterparty. Nobody is emailed until you approve and the agent calls `send_for_signature`
with `confirm: true` on a connection allowed to send. More in the [prompt library](/ai-agents/prompts).

## Server-side agents (API key)

For agents that run in your backend (your own product's assistant, a workflow, a scheduled job), authenticate with
your API key and configure each connection with [headers](/ai-agents/headers). Your code, not a consent screen,
decides the account, tenant, mode and allowed domains, so you can open one connection per customer of your product.

### Get your keys

1. Sign up at [app.sendforsign.com](https://app.sendforsign.com) and open the **API Keys** tab of the dashboard.
2. Copy your **API key** (`X-Sendforsign-Key`).
3. Copy a **client key** (`clientKey`) — the account space the agent works in. If you embed Sendforsign for several
   customers, [create a client](/api-reference/client/create) per customer and use its key.

<Warning>
  An API key gives full access to your account. Keep it out of prompts, repositories and chat transcripts; put it in
  environment variables or a secret store. Start new integrations with `X-Sendforsign-Agent-Mode: draft` so the agent
  cannot email anyone until you are ready.
</Warning>

| Header | Value |
|---|---|
| `X-Sendforsign-Key` | Your API key |
| `X-Sendforsign-Client-Key` | Your client key |

Recommended on top: `X-Sendforsign-Agent` (a name for this agent), `X-Sendforsign-On-Behalf-Of` (the person or
company it acts for), `X-Sendforsign-Agent-Mode` and `X-Sendforsign-Allowed-Domains`. Note that the header default
mode is `send`, unlike the consent screen. See the [headers reference](/ai-agents/headers).

<Tabs>
  <Tab title="OpenAI Agents SDK">
    ```python agent.py
    import asyncio, os
    from agents import Agent, Runner
    from agents.mcp import MCPServerStreamableHttp

    async def main():
        async with MCPServerStreamableHttp(
            name="sendforsign",
            params={
                "url": "https://api.sendforsign.com/mcp",
                "headers": {
                    "X-Sendforsign-Key": os.environ["SENDFORSIGN_API_KEY"],
                    "X-Sendforsign-Client-Key": os.environ["SENDFORSIGN_CLIENT_KEY"],
                    "X-Sendforsign-Agent": "contracts-agent",
                    "X-Sendforsign-On-Behalf-Of": "jane@customer.com",
                    "X-Sendforsign-Agent-Mode": "draft",
                },
            },
            cache_tools_list=True,
        ) as sfs:
            agent = Agent(
                name="Contracts",
                instructions="Prepare contracts from templates. Never send without the user's approval.",
                mcp_servers=[sfs],
            )
            result = await Runner.run(agent, "List my templates and draft an NDA for Acme Ltd.")
            print(result.final_output)

    asyncio.run(main())
    ```

## Troubleshooting

| Error | Cause |
|---|---|
| `401` and the app asks you to sign in again | The connection was disconnected or its refresh token expired or was reused. Connect again. |
| `401 Missing credentials` | Header connection without `X-Sendforsign-Key` or `Authorization: Bearer`. Check that your client passes headers to remote servers. |
| `400 Missing X-Sendforsign-Client-Key` | API-key auth also needs the client key header. |
| `Blocked by policy: this connection is read_only / in draft mode` | The tool needs a higher [agent mode](/ai-agents/accountability#agent-modes). For OAuth, reconnect and choose a different mode on the consent screen. |
| `Not executed: ... needs confirm: true` | Expected: the agent must ask the human, then call again with `confirm: true`. |
| `Blocked by policy: recipients outside the allowed domains` | A recipient's email is outside the allowed domains of this connection. |
| `405 Method not allowed` | The client tried SSE (`GET`). Use the Streamable HTTP transport. |

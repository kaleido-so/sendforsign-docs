## 18 November (later)

### MCP server: 33 tools
- Templates: `create_template`, `update_template` (with `{{field}}` markers), `create_pdf_template`,
  `create_template_from_contract`, `duplicate_template`, `delete_template`. `place_pdf_fields` and `fill_placeholders`
  work on templates too.
- Also new: `duplicate_contract`, `remove_field`, `update_recipient`, `remove_recipient`, `get_usage`, and
  `list_webhooks` / `create_webhook` / `delete_webhook` (creating and deleting need `confirm: true`). See [MCP tools](/ai-agents/tools).

### For people who connect AI apps
- **Settings → Connected AI apps** lists every app you connected over OAuth, its account, mode and last use, with Disconnect.
- **Agent actions in the contract timeline** (`sendforsign` components 2.3.5): which agent did what, for whom, and whether it was allowed or blocked.
  Also over the API: [Get agent actions](/api-reference/contract/agent_actions).
- The [privacy policy](/about/privacypolicy#ai-connectors-and-agents) now says what an AI app can access, what is logged and how to disconnect.

### Getting started
- The overview shows contracts sent this period against your plan, starter templates (Mutual NDA, Service agreement,
  Freelance contract) with field owners already set, and how to connect Claude, ChatGPT, Cursor or VS Code.

### Platforms
- [Usage](/api-reference/usage): contracts sent this period, in total and per client, so you can bill your own customers.
- Branding can be [read back](/api-reference/settings/branding#read-the-current-branding), and a custom signing domain is
  [checked](/api-reference/settings/branding#check-a-custom-signing-domain) before it is used. In the app: Settings → White-label.

### Fixes
- A recipient can sign only once, and only with a signing link.
- "Seen" is recorded once per recipient, also when your own UI loads the contract by its link, and fires your `seen` webhook.
- A PDF field at coordinate 0 is no longer treated as unset.

## 18 November

### Fields in the agent's text and PDF contracts over MCP

- `create_contract` and `update_contract` turn `{{Name}}`, `{{Name=Value}}`, `{{Name@any}}` and `{{Name@email}}`
  markers into fields with the right owner. See [MCP tools](/ai-agents/tools#create_contract).
- New tools `create_pdf_contract` (a PDF by https URL or base64) and `place_pdf_fields` (signature, date signed,
  full name, email and text fields, placed in percent of the page). The server now has 19 tools.
- The MCP server is listed in the official MCP registry as `com.sendforsign/mcp`.

### Field values are inserted as text

Field values written into a contract body (placeholder `update`, contract `create`/`update` with placeholders) are
now HTML-escaped, so a value can no longer add markup to the document. A value such as `Smith & Co` looks the same as
before. A field whose value is cleared now shows its `{{{name}}}` token instead of nothing, as in the editor.

## 12 November

### Sendforsign MCP server for AI agents

Any MCP client (Claude, ChatGPT, Cursor, the OpenAI Agents SDK or your own agent) can now work with contracts through
the remote MCP server at `https://api.sendforsign.com/mcp` (Streamable HTTP).

New features:
- 17 tools: templates and their fields, drafts from a template or from Markdown/HTML, filling fields, recipients with
  signing links, sending for signature, timeline, PDF download, archive, tenants for embedded products
- Field roles: the agent fills its own fields and leaves the counterparty's fields to the counterparty
- Sign in with Sendforsign: AI apps such as Claude, ChatGPT, Claude Code, Cursor and VS Code connect with OAuth 2.1
  (dynamic client registration, PKCE) by pasting the URL. On the consent screen the user picks the account, optionally a
  user the connector is limited to, what the agent may do (drafts only by default) and allowed recipient domains
- Guardrails for server-side agents set by the integrator in headers: agent modes (`read_only`, `draft`, `send`), `confirm: true` before any
  email or archive, a recipient domain allowlist, agent and on-behalf-of identity
- An audit log of agent actions, returned in the contract timeline (rolling out)

### Agent skill and AI agents docs

- A new [AI agents](/ai-agents/overview) section with recipes, a [prompt library](/ai-agents/prompts) and the
  headers and tools reference
- A [Sendforsign agent skill](/ai-agents/skills) (`SKILL.md`) for Claude Code, Claude apps, Codex and other agents
- [`/llms.txt`](https://sendforsign.com/docs/llms.txt) and [`/llms-full.txt`](https://sendforsign.com/docs/llms-full.txt)
  for language models
- Placeholder docs now cover `fillingType` (who fills a field) and `externalRecipientKey`

### AI+API is deprecated

AI+API (`aiapi.sendforsign.com`) is replaced by the MCP server and the agent skill. New integrations should use the
[MCP server](/ai-agents/mcp-quickstart). The [AI+API page](/api-reference/mcp/aiapi) stays available for existing
integrations.
